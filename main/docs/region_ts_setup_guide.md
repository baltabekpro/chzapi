# Подробное руководство по настройке регионов и ТС

## Введение

Данное руководство предназначено для детального объяснения процесса настройки связи между сертификатами, торговыми системами (ТС) и регионами в системе обработки отчетов ЦРПТ.

## Терминология

- **ТС (торговая система)** - уникальный идентификатор организации в системе ЦРПТ
- **ИНН** - идентификационный номер налогоплательщика
- **Регион** - логическая группировка ТС для удобного управления и анализа данных

## Подготовка к настройке

Перед началом настройки рекомендуется составить таблицу соответствия:

| Сертификат | ТС | ИНН | Регион | Email для отчетов |
|------------|----|----|--------|------------------|
| Иванов И.И. | тс42 | 7701234567 | Москва | moscow@company.com |
| Петров П.П. | тс54 | 5404123456 | Сибирь | siberia@company.com |

## Настройка сертификатов и ТС

### 1. Установка сертификатов

1. Запустите программу и выберите пункт "7. Установить сертификат из файла"
2. Следуйте инструкциям на экране для установки сертификата
3. Повторите для всех необходимых сертификатов

### 2. Добавление ТС-ИНН пар для сертификатов

Для каждого сертификата, который работает с несколькими ТС, необходимо указать соответствующие пары ТС-ИНН:

1. В главном меню выберите "3. Управление токенами и сертификатами"
2. Выберите "Добавить ТС-ИНН пару"
3. Выберите сертификат из списка
4. Введите ТС (например, "тс42")
5. Введите соответствующий ИНН (например, "7701234567")
6. Подтвердите добавление
7. При необходимости повторите для добавления других ТС-ИНН пар к этому сертификату

#### Пример файла cert_inns.json после настройки:

```json
{
  "Иванов Иван": [
    {"тс42": "7701234567"},
    {"тс77": "7701234567"}
  ],
  "Петров Петр": [
    {"тс54": "5404123456"},
    {"тс55": "5503987654"}
  ]
}
```

## Настройка регионов

### 1. Создание регионов

1. В главном меню выберите "9. Управление регионами"
2. Выберите "Добавить регион"
3. Введите идентификатор региона (например, "moscow")
4. Введите название региона (например, "Московский регион")
5. Введите email для отправки отчетов по региону (например, "moscow@company.com")
6. Повторите для создания всех необходимых регионов

### 2. Назначение ТС регионам

1. В главном меню выберите "9. Управление регионами"
2. Выберите "Назначить ТС региону"
3. Выберите регион из списка
4. Выберите "Добавить ТС в регион"
5. Введите идентификатор ТС или выберите из предложенного списка
6. Повторите для всех ТС, которые нужно добавить в этот регион
7. Повторите шаги 2-6 для всех остальных регионов

#### Пример файла regions.json после настройки:

```json
{
  "regions": [
    {
      "id": "moscow",
      "name": "Московский регион",
      "email": "moscow@company.com",
      "ts_list": ["тс42", "тс77"]
    },
    {
      "id": "siberia",
      "name": "Сибирский регион",
      "email": "siberia@company.com",
      "ts_list": ["тс54", "тс55"]
    }
  ]
}
```

## Проверка настройки

### 1. Проверка связи сертификатов и ТС

1. В главном меню выберите "3. Управление токенами и сертификатами"
2. Выберите "Просмотр информации о сертификатах"
3. Проверьте, что все сертификаты имеют правильные ТС-ИНН пары

### 2. Проверка регионов и их ТС

1. В главном меню выберите "9. Управление регионами"
2. Выберите "Просмотр списка регионов"
3. Для каждого региона проверьте, что список ТС соответствует ожидаемому

### 3. Тестовый запуск получения отчетов

1. В главном меню выберите "1. Запустить ежедневную обработку"
2. После завершения процесса проверьте, что отчеты сформированы для всех регионов
3. Проверьте папку output, чтобы убедиться в правильности группировки данных

## Типичные проблемы и их решения

### 1. Токен не получен для сертификата

**Проблема**: При обновлении токенов система не может получить токен для определенного сертификата.

**Решение**:
- Проверьте правильность указанных ТС-ИНН пар
- Убедитесь, что сертификат установлен корректно в хранилище КриптоПро
- Проверьте срок действия сертификата

### 2. Данные не группируются по регионам

**Проблема**: Отчеты формируются, но не распределяются по регионам корректно.

**Решение**:
- Проверьте, что все ТС назначены регионам в файле regions.json
- Убедитесь, что ТС в regions.json соответствуют ТС в cert_inns.json
- Проверьте наличие всех необходимых ТС-ИНН пар для сертификатов

### 3. Отчеты не отправляются на email

**Проблема**: Отчеты формируются, но не отправляются по электронной почте.

**Решение**:
- Проверьте правильность настроек в файле email_config.json
- Убедитесь, что указаны корректные email-адреса для регионов
- Проверьте доступность SMTP-сервера

## Расширенные сценарии

### 1. Реорганизация структуры регионов

Если вам нужно изменить структуру регионов (например, объединить два региона в один):

1. Создайте новый регион
2. Перенесите все ТС из старых регионов в новый регион
3. Удалите старые регионы

### 2. Передача ТС между сертификатами

Если ТС нужно передать от одного сертификата другому:

1. Удалите ТС-ИНН пару из старого сертификата
2. Добавьте ТС-ИНН пару к новому сертификату
3. Убедитесь, что ТС остается в правильном регионе

### 3. Автоматизация настройки больших списков

Для автоматизации настройки большого количества ТС и регионов рекомендуется:

1. Подготовить данные в Excel или CSV формате
2. Использовать скрипты конвертации для создания правильно форматированных JSON-файлов
3. Заменить существующие файлы cert_inns.json и regions.json

Пример скрипта можно найти в директории utilities системы.

## Заключение

Правильная настройка связи между сертификатами, ТС и регионами позволяет максимально эффективно использовать возможности системы обработки отчетов ЦРПТ. Регулярная проверка и обновление этих настроек помогут избежать проблем при получении и анализе данных.
